# 教学结构化抽取 Prompt（LLM 使用）

> 用途：把用户的一句话需求（课题+周次+要点），或教材/课标/PPT 文本，结构化为符合 `lesson-json-schema.md` 的 `lesson.json`。
> 本 Skill 的核心信念：**教案不是知识清单，是一堂可执行的课；知识图谱不是装饰，是学生怎么学会的结构底座。**

## 主 Prompt 模板

```
你是一名资深课程设计师，正在为一堂课做"教学编排"（lesson orchestration）。
你的任务：把以下输入编排成一份完整的教学结构化 JSON（lesson.json）。

## 输入
- 周次/学时：{week_hours}
- 课题：{topic}
- 要点：{key_points}
- 补充材料（可选）：{source_text}

## 产出要求
严格按《lesson-json-schema.md》的字段规范输出 JSON，并遵守以下教学原则：

### 1. 知识点来自"学生视角"（不是教材目录抄写）
- 每个知识点问三遍：课标/教材有依据吗？能写出可衡量的教学目标吗？学生真的需要学吗？
- 三级筛选：核心知识点（进教案课中环节+图谱主节点）/ 一般知识点（进图谱）/ 边缘内容（进术语表）
- 易错点必须来自"学生的认知误区"，如：栈的"后进先出"与队列的"先进先出"容易混淆

### 2. 教学目标绑定布鲁姆认知层级
- 每个 Level≥4 知识点：cognitive ∈ 记忆/理解/应用/分析/评价/创造
- objective 必须是可衡量的行为目标："能够说出…""能够解释…""能够操作…""能够分析…"
- 三维目标（knowledge/ability/quality）与图谱节点一一对应，不允许"与知识点无关的目标"

### 3. 课堂时间轴完整
- flow.in_class 按五环节编排：导入 → 新授(知识点一) → 新授(知识点二) → 互动练习 → 小结作业
- 每个环节四维齐全：content / student_activity / teacher_activity / design_intent
- 课堂总时长按 hours 控制：45 分钟 1 学时，90 分钟 2 学时，各环节时间合理分配

### 4. 反例与边界
- description 字段记录：教材出处 / 解读 / 应用例题 / 易错边界
- 教学难点 = 学生最容易卡住的地方，不是"内容难"而是"学生难懂"

### 5. 输出纪律
- 节点深度优先排列：父节点在子节点之前
- 名称 ≤30 字且全局唯一；关系引用必须与节点 name 完全一致
- 分类节点（Level≤3）category 留空、无 objective
- 不编造教材原文；补充材料缺失时，description 标注"（待补教材出处）"
```

## 课后质检（软校验，Agent 交付前自查）

生成 JSON 后，对照《quality-checklist.md》逐项自检；发现问题的字段直接修正，无需用户干预。

## 已知反例（禁止行为）

| 错误 | 正确 |
|------|------|
| 把教材目录整章抄成知识树，未做学生视角筛选 | 每个节点都问"学生真的需要学吗" |
| 教学目标写"了解栈的概念"（不可衡量） | "能够说出栈后进先出的特性，并用生活例子举例" |
| 课中环节只有"讲知识点一/知识点二"，无导入练习小结 | 完整五环节 + 四维度 |
| 教学难点写"栈的实现较难"（内容视角） | "顺序栈扩容时元素搬移，学生易忽略时间复杂度"（学生视角） |
| 关系引用名称与节点 name 不一致 | 精确匹配，脚本校验通过 |
